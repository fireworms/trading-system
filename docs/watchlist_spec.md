## 작업 전 먼저 할 것
기존 코드베이스를 먼저 파악해. 현재 FastAPI 백엔드 구조(라우터/모델/DB 세션), PostgreSQL 스키마, KIS API 클라이언트, Gemini 호출 모듈, Next.js 탭 구조와 컴포넌트 패턴을 확인하고 거기에 **일관되게** 통합해. 아래는 스펙이지 새 프로젝트가 아님 — 기존 네이밍/폴더 구조/에러 핸들링 컨벤션을 따를 것.

## 목적
자동매매 탭과 별개로, **중장기 관점 수동매매**용 관심종목 분석 탭. 핵심은 AI 예측이 아니라 **매매 일지** — 종목별·일자별로 "그날 내가 왜 이렇게 봤는지"를 데이터와 함께 타임스탬프로 박아두고 나중에 검증 가능하게 하는 것.

## 핵심 설계 원칙 (중요 — 이거 어기면 잘못 만든 거)
1. **AI 역할 = 데이터 집계 + 생각 구조화, 예측 아님.** Gemini한테 "오를까 내릴까" 시키지 말고, 흩어진 지표·수급·뉴스를 모아서 판단 가능한 구조로 정리하게 시킴. 출력에 근거 없는 방향성 단언("단기 조정 후 상승") 금지.
2. **분석 트리거는 이벤트 기반 + 수동.** 매일 자동 분석 안 함(중장기인데 EPS/PER은 분기마다 바뀌어서 매일 돌리면 입력이 거의 안 변해 노이즈만 쌓임). 트리거: 실적발표 / 주요공시 / 수급 급변 / 주가 급변 + 사용자가 누를 때.
3. **분석할 때 입력 데이터 스냅샷도 같이 저장.** 그날 쓴 지표값 + 뉴스 출처(URL/제목)를 분석 결과와 함께 DB에 저장. 안 그러면 6개월 뒤에 AI가 뭘 보고 그렇게 판단했는지 재구성 불가 = 일지 가치 반토막.
4. **recency bias 억제.** Gemini가 최신 뉴스에 과반응하는 거 중장기엔 버그. 프롬프트에서 "펀더멘털 우선, 뉴스는 보조 + 일시적 노이즈냐 구조적 변화냐 구분"을 명시적으로 강제.

## 데이터 모델 (기존 스키마 스타일에 맞춰 조정)
- `watchlist_stocks`: ticker, name, sector(nullable), memo, added_at
- `stock_analyses`:
  - id, ticker, analysis_date, created_at, gemini_model
  - 구조화 출력 필드 (아래 "출력 구조" 참조) — JSONB 컬럼 하나로 묶어도 됨
  - `input_snapshot` (JSONB): 그날 KIS 지표 raw + 수급 데이터 + 사용된 뉴스 출처 리스트
  - `raw_response` (Gemini 원문, 디버깅용)
- (선택) `analysis_triggers`: 어떤 이벤트로 분석이 돌았는지 기록 (trigger_type)

## API 엔드포인트
- 관심종목 CRUD: 추가 / 삭제 / 목록 / 메모 수정
- `POST /analyze` (ticker, date, trigger_type): KIS 6개월 지표 수집 → 아래 분석 입력 데이터 수집 → Gemini 호출 → 스냅샷+결과 저장 → 반환
- `GET /analyses/{ticker}`: 일자별 분석 이력 (리스트)
- `GET /analyses/{id}` (또는 ticker+date): 단일 분석 상세

## 분석 입력 데이터 — 우선순위순
KIS API로 실제 뭐가 오는지 먼저 확인하고, **없는 건 가짜 엔드포인트로 채우지 말고 "데이터 없음"으로 플래그** 처리해. 컨센서스·일부 펀더멘털은 KIS에 없을 가능성 큼.

1. **펀더멘털 심화** (6개월 PER보다 중요): 분기 매출/영업이익/순이익 YoY 추세, 영업이익률, ROE, 부채비율, PER/PBR 밴드(자기 과거 및 동종업종 대비)
2. **컨센서스**: 증권사 목표주가, 실적 추정치 (forward — trailing 지표 보완). KIS에 없으면 별도 소스 필요하다고 플래그
3. **수급** (한국시장 핵심): 외국인/기관 3~6개월 누적 순매수 추세, 외국인 보유비중 변화. KIS `inquire-investor` (주식현재가 투자자) 엔드포인트로 일별 개인/외국인/기관 순매수 수량+금액 조회 가능. ※ 기존 수급 분석 모듈 있으면 재사용
4. **공시/뉴스** (Gemini 검색): DART 공시(실적/유증/자사주/대형계약/합병), 섹터·테마 동향, 정책 모멘텀
5. **매크로 (섹터 한정)**: 환율(수출주), 금리, 유가·원자재(해당 섹터), 코스피/코스닥 국면
6. **리스크 플래그**: 관리종목/거래정지 리스크, 최대주주 지분 변동, 소송/규제

## Gemini 분석 프롬프트 설계
시스템 프롬프트에 명시:
- 역할: 데이터를 구조화하는 애널리스트. 주가 방향 예측 금지.
- 입력: 위 지표 + 수급 + 뉴스
- 펀더멘털 우선, 뉴스 보조. 뉴스는 "일시적 노이즈 vs 구조적 변화"로 구분해 다룰 것.
- 출력은 아래 구조의 JSON으로만 (preamble/markdown 백틱 없이 → 파싱 안정성)

**출력 구조 (JSON 필드):**
- `논거`: 현재 상태 요약 (데이터 기반)
- `단기_촉매`: 단기 이벤트 + 예상 시점 (있으면)
- `장기_논거`: 중장기 투자 논거
- `무효화_조건`: "이 신호 뜨면 내 판단이 틀린 거다" — falsifiable하게. ※ 제일 중요, 절대 빼먹지 말 것
- `밸류_코멘트`: 현재 밸류에이션 평가 (밴드 대비 싼지/비싼지)

## 판단 구조 보강 (2026-08-28)
배경: SK하이닉스 분석 리포트 외부 리뷰에서 드러난 구멍 — 무효화_조건은 있는데 **반증할 대상(주장)이 없고**, 조건 자체가 이미 충족·임박했거나 기저효과에 종속돼 대부분 못 쓰는 상태였다. 밸류 코멘트의 유일한 "비싸다" 근거였던 PBR 퍼센타일은 장부가 시점차 왜곡을 안고 있었다.

### 1. 핵심_주장 필드 — falsifiability 복구
"이 분석이 성립하려면 참이어야 하는 명제" 한 문장을 강제하고, 무효화_조건이 그 명제를 반증하도록 연결. **매수/관망/회피 결론이나 진입가 강제는 채택하지 않음** — ai_probability 폐기 근거(검증 515건, LLM 수치 단정에 예측력 없음)와 이 탭의 "감시는 기계, 판단은 사람" 성격에 정면으로 어긋난다. 주장만 명시하면 예측 없이 falsifiability가 회복된다.

### 2. 무효화_조건 품질 게이트 (`invalidation.screen_conditions`)
구조 검증(normalize)을 통과해도 **감시 가치가 없는 조건**을 앱이 결정론으로 거른다. 판정 재료는 input_snapshot + 적재 수급뿐 — 추가 API 0회, LLM 0회.
- **이미 충족/임박**: 임계의 70%(`_PROXIMITY_RATIO`) 이상 도달 → 조건이 아니라 예정된 사건
- **기저효과 종속**: earnings의 YoY 성장률 임계 절대값 100% 초과 금지 → 마진 등 절대 수준 지표 유도
- **방향 역전**: valuation `below`(싸지면 무효화)는 강세 논거의 반증이 아님
- **비이례 임계**: fx 레벨이 최근 3개월 밴드(low_3m~high_3m) 안이면 평상시 변동
탈락 시 결함 사유를 붙여 **1회 재요청** → 그래도 남으면 삭제가 아니라 **manual 강등**(서술 보존, 자동 감시에서만 제외). 재요청 응답은 자동 감시 가능 조건이 *늘었을 때만* 교체.

### 3. 밸류 시나리오 역산 (`analyzer._valuation_scenarios`)
"현재 상황이 유지되면 얼마까지" 질문에 답하되, **LLM이 목표주가를 생각해내지 않는다**. 앱이 `현재가 × 목표배수 ÷ 현재배수`로 역산 — 주식수를 거치지 않아 발행주식수 오차가 끼지 않는다. PER 밴드(실적연도 확정분) 상단/중앙/하단 + 컨센서스 반영 + PBR 5년 밴드, **상단만 내면 편향이므로 하단도 같은 산식으로 대칭 생성**. LLM 역할은 표에서 논거와 정합적인 행을 고르고 그 "전제"를 밝히는 것뿐.
결정론 경고(무시 금지, 프롬프트 규칙 8):
- **peak_earnings**: TTM 순이익 > 과거 실적연도 최고치 → 사이클 종목은 이익 정점에서 멀티플이 밴드 하단에 형성되는 게 정상(peak earnings = trough multiple). 멀티플 회복 시나리오보다 이익 지속성이 선행 조건
- **영업외 요인**: 순이익 > 영업이익 × 1.2 → per_ttm 분모가 일회성으로 부풀려졌으면 PER 기반 상단 전체가 과대
- **장부가 시점차**: 최근 분기 BPS 기준 PBR과 밴드 기준 PBR 괴리 15%+ → 해당 PBR 행에 `신뢰도: 낮음` 표시(표 밖 경고문만으로는 -85% 같은 숫자가 그대로 읽힌다)
**사이클 종목 대응 (2026-08-28 하이닉스 실검증에서 드러남)**:
- **KIS estimate의 `per` 행이 통째로 비어 오는 종목이 있다** — 하이닉스 실측 `per: None`. 이 경우 PER 시나리오가 전부 사라져 답이 PBR 행만 남았다. → 자체 5년 PER 밴드(월봉 종가 ÷ 당시 확정 연간 EPS, **적자 연도 제외** — 음수 PER이 섞이면 역산이 깨진다)를 1차로 쓰고 estimate의 per는 보조. forward PER도 `현재가 ÷ 컨센 EPS`로 자체 산출
- **밴드 꼬리 절사 (min/max → p20/p80)**: 사이클 종목의 PER 밴드 상단은 **이익 바닥 시기에 만들어진다**(EPS가 0에 수렴하면 PER 폭증). 하이닉스 실측에서 PER 상단 77.21배 → +936%가 나왔다. min/max는 참고 통계로만 남기고 역산에는 분위수를 쓴다
- **이익 국면 불일치 플래그**: peak_earnings면 PER 행 전체에 `신뢰도: 낮음 (이익 피크 × 과거 이익국면 배수)`. 피크 이익 × 바닥 시기 배수 = 이중 계상 — PBR 장부가 시점차와 대칭 처리
- **과거 배수를 안 쓰는 행**: `현재 배수 유지 × 연도별 컨센서스` (함의주가 = per_ttm × 컨센 EPS). 이익 국면 불일치도 장부가 시점차도 타지 않아 **사이클 정점에서 유일하게 성립하는 역산**이며, "현재 상황 그대로 흘러갈 시 얼마까지"의 문자 그대로의 답이다. 하이닉스는 이 행 2개만 무플래그로 남았고 LLM이 정확히 그것만 인용한 뒤 "밴드 회귀 시나리오는 현재 국면에서 유효성이 떨어진다"고 결론냈다 (규칙 8 의도대로)
- **잔여 한계**: p80으로 잘라도 이익 바닥 구간 개월이 많으면 상단이 여전히 높다(하이닉스 43.98배). 종목 하나로 임계를 더 조이는 건 과최적화 — 플래그가 실효를 막고 있으므로 표본 축적 후 판단

"하지 말 것"의 *매매 신호 단정 표시* 금지와 충돌하지 않는다 — 등급·점수·매수 문구가 아니라 전제가 붙은 산술 환산이고, 전제가 깨지면 그 행이 무효임을 표에 명시한다.

### 4. 수치 정합 교정
- **PBR 기준 병기**: `pbr_recent_q`(최근 분기 BPS 기준) + `pbr_band_5y.basis` 라벨. 밴드 퍼센타일 자체는 과거·현재 모두 연간 BPS 기준이라 내부 일관성이 있다 — "퍼센타일이 통째로 무의미"가 아니라 **시점차 크기가 이례적인 구간에서 함께 읽을 값이 필요**했던 것
- **순이익 품질**: `ni_margin_q_pct` + 순이익 > 영업이익 시 `ni_over_op_note`. per_trailing 왜곡만 의심하고 per_ttm 왜곡은 검증 안 하던 비대칭 해소. YTD 차분이 깨져도 같은 신호가 떠 **차분 회귀 감시 겸용**
- **수급 일평균 분모**: `_avg`가 결측일을 제외한 실제 거래일 수를 함께 반환 → judgment가 "최근 4거래일 일평균"처럼 실제 분모를 노출. 5일 창에서 4로 나누고 "5일 일평균"이라 쓰던 라벨 거짓말 교정
- **공시 키워드**: 자본변동에 `증권신고서/해외증권/예탁증서/신주발행/주식발행` 추가 — ADR·해외DR 신주발행(희석)을 통째로 놓치던 구멍
- **날짜 환각 방어**: 실적 발표일·공시일은 dart_disclosures의 rcept_dt에서만 인용(프롬프트 규칙 9). 정기보고서 **법정 제출기한 ≠ 실적 발표일** — 16:30 캘린더 알림이 계산하는 기한을 LLM이 발표일로 착각한 사례
- **촉매/양방향**(규칙 10·11): 단기_촉매는 기준일 이후 이벤트만(발표 완료 건은 논거 배경으로), 장기 논거에 인용한 이벤트가 단기 수급에 반대로 작용하는지(희석·보호예수 해제·차익거래) 검토 강제
